# Agent 分步创建流程后端契约请求

## 背景

AgentHub 新建 Agent 调整为四步全页向导：基础设定、头像、角色设定稿、技能。基础设定生成成功后才建立“创建中草稿”，创建完成后仍是未发布草稿。

前端不会继续使用“先创建空 Agent，再进入构建页”的旧流程，也不会在 Live 模式用本地数据模拟成功。

## 需要后端支持的能力

### 1. 原子生成基础设定并建立创建中草稿

一次请求完成：

1. 接收产品方案规定的五项输入：Agent 名称、角色是谁、与用户的关系、主要互动、性格与表达标签。
2. 调用系统 Motherland 生成 Agent 简介、角色系统提示词、开场白和 3 条示例对话。
3. 仅在生成成功后创建 Agent 与创建中草稿。
4. 返回 Agent 标识、完整生成内容和当前 `draft_revision`。
5. 任一步失败均不留下空 Agent 或不完整草稿。

### 2. 查询创建进度并继续创建

资产库需要识别“创建中”记录，并获得：

- 当前完成步骤；
- 已确认的基础设定、头像和角色设定稿；
- 已选技能的稳定引用；
- 当前 `draft_revision`；
- 最近保存时间和保存状态。

继续创建时应返回同一份服务端草稿，不应由浏览器本地状态作为 Live 数据真相。

### 3. 统一 Revision 写入

以下确认动作需要接收 `expected_draft_revision`，成功后返回新的 Revision：

- 确认或更新基础设定；
- 确认头像；
- 确认角色设定稿；
- 更新技能选择；
- 标记四步创建完成。

Revision 冲突统一返回可识别的冲突码和服务端当前 Revision，避免覆盖其他窗口或其他操作者的修改。

### 4. 候选与草稿隔离

- Motherland 生成候选不得直接写入已确认头像或角色设定稿。
- 只有用户点击确认后的内容才进入草稿。
- 重新生成候选不得覆盖已确认内容。
- 草稿依赖发生变化时，后端应能保存或返回头像、角色设定稿的待更新状态。

### 5. 技能稳定引用

技能选择需要返回并保存可用于发布快照的稳定技能版本引用。前端只展示本地化名称、描述、图标和可用状态，不使用英文标识作为产品字段。

## 验收约束

- 创建完成记录保持未发布，不生成版本号或 Version Hash。
- 创建中草稿可在退出、刷新、换浏览器后继续。
- 未确认候选不进入草稿和版本快照。
- Live 模式所有成功状态均来自服务端真实响应。
