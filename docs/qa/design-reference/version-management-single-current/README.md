## 设计目标

这套设计只保留一个“平台当前版本”，所有 Client 不再独立选择 Agent 版本。

核心流程：

```text
编辑平台当前版本
→ 形成唯一当前草稿
→ 测试并发布
→ 生成新版本号和 Version Hash
→ 更新平台当前版本
```

## 核心交互规则

### 平台当前版本

- 一个 Agent 同一时间只有一个平台当前版本。
- 平台当前版本不可直接修改；点击编辑后形成当前草稿。
- 发布成功后，新版本原子替换旧版本成为平台当前版本。
- 版本号表示发布顺序，Version Hash 表示确定的版本内容。

### 当前草稿

- 每个 Agent 最多只有一个当前草稿。
- 草稿基于平台当前版本或历史版本创建。
- 草稿没有最终 Version Hash，发布成功后才生成。
- 保存、测试和预览草稿都不影响平台当前版本。

### Session

- 新 Session 和无 Session 请求使用平台当前版本。
- 已创建 Session 继续使用创建时绑定的版本。
- 历史版本可以继续服务已绑定 Session，但不再接收新 Session。

### Client

- Client 不提供独立版本选择、单独更新或单独回退。
- AgentHub 托管 Client 发布后立即跟随。
- 远程 Client 在下次同步时跟随。
- Client 离线本身不阻止发布；明确不兼容才阻止发布。

### 历史版本

- 历史版本不可修改。
- 恢复历史内容只能通过“基于此版本创建草稿”。
- 后续发布使用连续的新版本号并生成新的 Version Hash。
- 不提供“直接设为平台当前版本”操作。

### 媒体与导出

- 运行所需媒体成品随 Agent 版本固化。
- Version Hash 覆盖配置、媒体文件 Hash，以及知识和技能版本引用。
- 本地 Client 只能导出平台当前版本。
- 已导出的运行包不会随后续发布自动更新。

## 统一文案

- 使用“平台当前版本”，不使用“各 Client 当前版本”。
- 使用“当前草稿 · 基于 v4”，不提前把草稿称为 v5。
- 草稿阶段显示“Version Hash：发布后生成”。
- Client 状态使用“已跟随”“等待下次同步”“最近确认”，不使用“更新到 v5”。
- 历史恢复使用“基于此版本创建草稿”，不使用“回退运行版本”。

## 其他状态

以下状态复用统一组件，不再单独出完整页面：

- 发布成功：返回版本页，展示新版本号、Version Hash 和成功提示。
- 导出成功：关闭弹窗并展示运行包下载结果与导出记录。
- 同步完成：Client 状态由“等待下次同步”更新为“已同步”。
- 当前已有草稿：从历史版本创建草稿前，先确认是否覆盖未发布修改。
