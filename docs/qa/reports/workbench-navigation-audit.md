# 工作台导航栏审查

## 审查范围

- 页面：`/workbench`
- 用户目标：快速识别当前位置，并在工作空间核心模块间切换
- 证据：`docs/qa/images/workbench-navigation-audit-01.png`
- 状态：工作台已加载，“继续构建”分组标题已移除

![工作台导航栏审查](../images/workbench-navigation-audit-01.png)

## 步骤

1. 进入工作台：健康。当前项的底色、文字颜色和左侧强调线能明确表达选中状态。
2. 扫描主导航：基本健康。图标、标签和点击区域一致，但八个入口全部平铺，业务层级不够明显。
3. 识别能力状态：需要优化。多个灰色圆点没有文字说明，容易被理解为未读消息、异常或通知。
4. 定位设置：健康。设置固定在底部，与主业务入口分离。

## 优点

- 导航使用语义化 `nav` 和链接，当前页具备 `aria-current="page"`。
- 图标尺寸、文字字号、行高和选中态保持一致。
- 单项最小高度为 48px，键盘和指针操作空间充足。
- Agent 工作区已有 88px 紧凑导航模式，可作为工作空间导航折叠方案的基础。

## UX 风险

### P1：灰色状态圆点语义不清

- 位置：工作台、资源库、数据分析、治理中心、收益中心右侧。
- 证据：圆点没有标签或图例，不同用户可能理解为未读、离线、异常或待办。
- 影响：增加理解成本，也让导航产生不必要的视觉噪音。
- 建议：优先移除圆点；如果必须表达能力未接入，使用明确的“规划中”说明，并避免在每一项重复展示。

### P2：平台入口和经营入口缺少分组

- 位置：接入管理与应用运营之间。
- 证据：资产、资源、接入、运营、分析、治理和收益全部处于同一层级。
- 影响：入口数量增加后，用户需要逐项阅读才能定位。
- 建议：用一条轻量分隔线将“资产与接入”和“运营与治理”分开；暂不增加分组标题，避免继续占用纵向空间。

### P2：工作空间页面缺少桌面折叠能力

- 位置：224px 工作空间侧栏。
- 证据：Agent 工作区已有 88px 图标栏，但工作空间页面始终保持完整侧栏。
- 影响：在 1280px 或浏览器放大场景下，内容区被明显压缩。
- 建议：复用现有 88px 紧凑模式，增加手动折叠按钮并记住用户选择；默认仍保持完整菜单。

## 可访问性风险

- 灰色状态圆点没有可访问名称，辅助技术无法获知它表示“规划中”。
- 截图无法确认文字与背景的精确对比度，也不能代替键盘焦点、缩放重排和屏幕阅读器测试。

## 建议顺序

1. 移除无语义状态圆点。
2. 在接入管理与应用运营之间增加轻量分隔。
3. 单独设计并实现工作空间侧栏的手动折叠。
4. 保留当前 14px 标签、21px 图标、48px 点击高度和选中态，不继续缩小。
